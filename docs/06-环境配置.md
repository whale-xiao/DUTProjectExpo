## 3. 首次搭建（换机器/从头装）

### 第 1 步：建库

MySQL 服务运行后（Windows 服务），执行（会提示输入 root 密码）：
```bash
mysql -uroot -p < "这里修改路径\demo\backend\scripts\init.sql"
```
脚本创建 `project_showcase` 库（utf8mb4_general_ci，5.7/8.0 通用）。

### 第 2 步：后端配置

```bash
cd "这里修改路径\demo\backend"
cp .env.example .env        # 然后编辑 .env，把 DB_PASSWORD 改成你的 root 密码
go mod tidy                 # 首次拉依赖（会自动下载 go 1.26 工具链）
```

`.env` 关键项见 §4；`.env` 已被 `.gitignore` 忽略，不要提交。

### 第 3 步：启动后端（自动建表 + 种子）

```bash
go run .
```
首次会看到：
- `✅ 数据库已连接并完成自动迁移`（自动创建 9 张表）
- `✅ 已创建管理员账号 "admin"`（默认密码见 .env `ADMIN_INIT_PASSWORD`）
- `✅ 已写入演示数据：分类 4、示例项目 15`（仅空库时写入）

验证：`curl http://localhost:8080/api/health` 应返回 `"db":"connected"`。

### 第 4/5 步：前台 / 后台前端

```bash
cd "这里修改路径\demo\frontend-showcase" && npm install && npm run dev   # :5173
cd "这里修改路径\demo\frontend-admin"    && npm install && npm run dev   # :5174
```

前端**不需要** `VITE_API_BASE_URL`：开发期由 Vite 代理把 `/api`、`/uploads` 转发到 :8080，代码里始终用相对路径（生产同源 Nginx 反代，见 §8）。

## 4. 后端 `.env` 配置说明

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `SERVER_PORT` | 8080 | 后端监听端口 |
| `DB_HOST/DB_PORT` | 127.0.0.1 / 3306 | MySQL 地址 |
| `DB_USER` | root | 数据库账号 |
| `DB_PASSWORD` | 空 | ⚠️ 必填你的密码 |
| `DB_NAME` | project_showcase | 数据库名（与 init.sql 一致） |
| `JWT_SECRET` | dev-only-change-me | ⚠️ 生产必改随机长串 |
| `ADMIN_USER` | admin | 自动创建的超级管理员 |
| `ADMIN_INIT_PASSWORD` | admin123456 | 其初始密码，首登后改密 |
| `UPLOAD_DIR` | ./uploads | 图片本地存储目录 |
| `STORAGE_DRIVER` | local | 一期本地；二期 oss |

后端启动时会：连库 → AutoMigrate 建表 → 种子 admin +（空库）演示数据。

## 7. 常见问题（实测对照）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 后端 `bind: Only one usage…` | 8080 已被占用（残留进程/他人实例） | 结束占用进程再 `go run .`；查 `netstat -ano \| grep :8080`，`taskkill //PID <pid> //F` |
| 后端 `Access denied for user 'root'` | `.env` 密码为空/错误 | 改 `backend\.env` 的 `DB_PASSWORD` |
| 前端接口 502 / 白屏 | 后端没起 | 先起后端；确认 `.env` 库能连上 |
| `database ... doesn't exist` | 未执行建库 | `mysql -uroot -p < backend/scripts/init.sql` |
| 后台 admin 登录失败 | 密码不是默认值 | 已改密用改后密码；或删库重建让种子重置 |
| 中文乱码 | 连接/表字符集不一致 | 统一 utf8mb4（init.sql 已含）；确认 DSN `charset=utf8mb4` |
| 后台保存项目报"项目名称已存在" | 同名项目（含软删残留） | 改名或从数据库清理软删行 |
| 前端跨域报错 | 直接用后端 URL 而非代理 | 开发用相对路径走 Vite 代理即可 |

## 8. Docker 一键部署（已实现并实测通过）

三个服务一条命令拉起，**本机无需安装 Go / Node / MySQL**（Docker 除外）。

```bash
docker compose up -d --build     # 首次构建约 3–5 分钟（拉基础镜像 + 两个前端 npm ci）
docker compose ps                # mysql 与 backend 应为 healthy，nginx 为 running
docker compose logs -f backend   # 观察 AutoMigrate 与种子日志
docker compose down              # 停止（保留数据卷）
docker compose down -v           # 停止并清空数据，下次启动重新建表 + 灌种子
```

| 入口 | 地址 |
| --- | --- |
| 前台展示站 | http://localhost |
| 管理后台 | http://localhost:8081 （admin / admin123456） |

### 8.1 服务编排

| 服务 | 镜像 | 说明 |
| --- | --- | --- |
| `mysql` | `mysql:8.0` | 官方镜像；`init.sql` 挂到 `/docker-entrypoint-initdb.d/`（**只建库**，表由 GORM AutoMigrate 建）；数据在命名卷 `mysql_data` |
| `backend` | 自建 `dut-expo/backend` | 多阶段：`golang:1.26-alpine` 编译 → `alpine:3.20` 运行，**成品约 14MB**；无 cgo，`CGO_ENABLED=0` 静态二进制 |
| `nginx` | 自建 `dut-expo/nginx` | 多阶段：两个 `node:22-alpine` 阶段分别构建前台/后台 → `nginx:alpine`；一个进程托管两个站点并反代 API |

### 8.2 三个必须知道的坑（都已在实现里规避）

1. **必须等 MySQL healthy 后端才启动**。后端 `main.go:16` 连不上库**不退出、不重试**，会带着 nil db 起服务且不会自愈。compose 用 `depends_on: mysql: {condition: service_healthy}` + `mysqladmin ping` 健康检查兜住。
2. **`init.sql` 只在数据卷为空时执行一次**。改了建库脚本重启容器不会生效 —— 要么 `docker compose down -v` 删卷重来，要么手动进容器执行。
3. **`uploads/` 必须随镜像分发**。种子数据的封面 URL 全指向 `/uploads/cover/*.jpg`（17 张），镜像里少了这一步就全站图片 404。用命名卷 `upload_data` 时 Docker 会用镜像内容初始化空卷，所以图不会丢、后续上传也持久化。

### 8.3 端口与路径约束

- 前台 `:80`、后台 `:8081`。两个前端都是 history 模式且 Vite 未设 `base`，构建产物资源写死 `/assets/…`，因此**只能分端口，不能塞进 `/admin/` 子路径**。
- 后端 8080、MySQL 3306 **均不对外发布**，只走 compose 内部网络（`DB_HOST=mysql`）。本机已装 MySQL 占用 3306 也不冲突。
- 两个 server 块都配了 `try_files $uri $uri/ /index.html`，`/project/3`、`/projects/3/edit` 等深链刷新不会 404。
- `/api` 与 `/uploads` 由 nginx 反代到后端，与开发期 Vite 代理行为一致，前端代码零改动。

### 8.4 配置与数据运维

- 可覆盖变量写在根目录 `.env`（模板见根目录 `.env.example`）；不创建 `.env` 时 compose 内的默认值也能直接跑。
- 备份：`docker compose exec mysql mysqldump -uroot -pexpo_root_pwd project_showcase > backup.sql`
- 重置演示数据（保留管理员）：`docker compose exec -T mysql mysql -uroot -pexpo_root_pwd < backend/scripts/drop.sql`，再 `docker compose restart backend`。

### 8.5 上云

同一份 compose 可直接部署到阿里云 ECS：把 `.env` 里 `DB_PASSWORD` / `JWT_SECRET` / `ADMIN_INIT_PASSWORD` 换成强配置（见 §9），外层加 HTTPS。图片二期迁 OSS 时只换 `STORAGE_DRIVER`，表结构与业务代码不动。

### 8.6 WSL（可选）

Ubuntu 内装 **Go 1.26.x**（勿装 1.24，见 §2），源码放 WSL 文件系统（勿 `/mnt/d`，IO 慢）；VSCode Remote-WSL 打开。

## 9. 安全提醒（上云前必改）

1. `JWT_SECRET` → 随机长串（`openssl rand -hex 32`）
2. `ADMIN_INIT_PASSWORD` → 强密码并首登后到库里改
3. 不把 `backend\.env`、`.env.production` 提交 Git
4. CORS 上线后从"允许全部"收紧为站点白名单（见 router.go 注释）
