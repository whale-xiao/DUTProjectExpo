## 3. 首次搭建（换机器/从头装）

### 第 1 步：建库

MySQL 服务运行后（Windows 服务），执行（会提示输入 root 密码）：
```bash
mysql -uroot -p < "这里修改路径\demo\backend\scripts\init.sql"
```
脚本创建 `project_showcase` 库（utf8mb4_general_ci，5.7/8.0 通用）。

### 第 2 步：后端配置

```bash
cd "这里修改路径\demo\backend"
cp .env.example .env        # 然后编辑 .env，把 DB_PASSWORD 改成你的 root 密码
go mod tidy                 # 首次拉依赖（会自动下载 go 1.26 工具链）
```

`.env` 关键项见 §4；`.env` 已被 `.gitignore` 忽略，不要提交。

### 第 3 步：启动后端（自动建表 + 种子）

```bash
go run .
```
首次会看到：
- `✅ 数据库已连接并完成自动迁移`（自动创建 9 张表）
- `✅ 已创建管理员账号 "admin"`（默认密码见 .env `ADMIN_INIT_PASSWORD`）
- `✅ 已写入演示数据：分类 4、标签 7、示例项目 3`（仅空库时写入）

验证：`curl http://localhost:8080/api/health` 应返回 `"db":"connected"`。

### 第 4/5 步：前台 / 后台前端

```bash
cd "这里修改路径\demo\frontend-showcase" && npm install && npm run dev   # :5173
cd "这里修改路径\demo\frontend-admin"    && npm install && npm run dev   # :5174
```

前端**不需要** `VITE_API_BASE_URL`：开发期由 Vite 代理把 `/api`、`/uploads` 转发到 :8080，代码里始终用相对路径（生产同源 Nginx 反代，见 §8）。

## 4. 后端 `.env` 配置说明

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `SERVER_PORT` | 8080 | 后端监听端口 |
| `DB_HOST/DB_PORT` | 127.0.0.1 / 3306 | MySQL 地址 |
| `DB_USER` | root | 数据库账号 |
| `DB_PASSWORD` | 空 | ⚠️ 必填你的密码 |
| `DB_NAME` | project_showcase | 数据库名（与 init.sql 一致） |
| `JWT_SECRET` | dev-only-change-me | ⚠️ 生产必改随机长串 |
| `ADMIN_USER` | admin | 自动创建的超级管理员 |
| `ADMIN_INIT_PASSWORD` | admin123456 | 其初始密码，首登后改密 |
| `UPLOAD_DIR` | ./uploads | 图片本地存储目录 |
| `STORAGE_DRIVER` | local | 一期本地；二期 oss |

后端启动时会：连库 → AutoMigrate 建表 → 种子 admin +（空库）演示数据。

## 5. 日常启动（三终端）

```bash
# 终端 1：后端（:8080）
cd "这里修改路径\demo\backend" && go run .

# 终端 2：前台（:5173）
cd "这里修改路径\demo\frontend-showcase" && npm run dev

# 终端 3：后台（:5174）
cd "这里修改路径\demo\frontend-admin" && npm run dev
```
浏览器：
- 前台 http://localhost:5173
- 后台 http://localhost:5174（登录：`admin` / `admin123456`，改密见 .env）

> 前端要联调，**后端必须同时在跑**（前端把 /api 代理到 8080）。

## 7. 常见问题（实测对照）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 后端 `bind: Only one usage…` | 8080 已被占用（残留进程/他人实例） | 结束占用进程再 `go run .`；查 `netstat -ano \| grep :8080`，`taskkill //PID <pid> //F` |
| 后端 `Access denied for user 'root'` | `.env` 密码为空/错误 | 改 `backend\.env` 的 `DB_PASSWORD` |
| 前端接口 502 / 白屏 | 后端没起 | 先起后端；确认 `.env` 库能连上 |
| `database ... doesn't exist` | 未执行建库 | `mysql -uroot -p < backend/scripts/init.sql` |
| 后台 admin 登录失败 | 密码不是默认值 | 已改密用改后密码；或删库重建让种子重置 |
| 中文乱码 | 连接/表字符集不一致 | 统一 utf8mb4（init.sql 已含）；确认 DSN `charset=utf8mb4` |
| 后台保存项目报"项目名称已存在" | 同名项目（含软删残留） | 改名或从数据库清理软删行 |
| 前端跨域报错 | 直接用后端 URL 而非代理 | 开发用相对路径走 Vite 代理即可 |

## 8. WSL / Docker / 上云（方向预留）

- **后端迁 WSL（可选）**：Ubuntu 内装 **Go 1.26.x**（勿装 1.24，见 §2），源码放 WSL 文件系统（勿 /mnt/d，IO 慢）；VSCode Remote-WSL 打开。
- **容器期（第 7 周起）**：启动 Docker Desktop；后端经 `go run` → 二进制 → 多阶段 Dockerfile；前端 `npm run build` → dist 进 Nginx 镜像；MySQL/Redis 用官方镜像 + 数据卷。`docker-compose.yml` 编排 4 服务，一条 `up -d`。
- **上云**：同一份 compose 部署到阿里云 ECS；Nginx 同源反代 `/api`、`/uploads`（此时前端无需代理/跨域）；`DB_PASSWORD`、`JWT_SECRET`、`ADMIN_INIT_PASSWORD` 一律换成云上强配置；图片二期迁 OSS。

---

## 9. 安全提醒（上云前必改）

1. `JWT_SECRET` → 随机长串（`openssl rand -hex 32`）
2. `ADMIN_INIT_PASSWORD` → 强密码并首登后到库里改
3. 不把 `backend\.env`、`.env.production` 提交 Git
4. CORS 上线后从"允许全部"收紧为站点白名单（见 router.go 注释）
