## 1. 设计原则

| 原则 | 来源 | 落地 |
| --- | --- | --- |
| 搜索即入口 | Reddit | 首页中央搜索框，即时联想直达 |
| 作品即主角 | Pixiv | 详情页让作品本身成为视觉核心 |
| 卡片即判断 | 小红书 | 卡片一眼看懂，封面驱动点击 |
| 沉浸 vs 高效 | — | 前台沉浸浏览，后台快速编辑 |

---

## 2. 信息架构

```
首页（搜索 + 推荐信息流）
   ├── 全部项目（标签筛选浏览）
   ├── 搜索联想
   └── 项目详情（作品文章）
          └── 章节：标题 / 文本 / 图片（图文混排）
```

后台：

```
登录 ──▶ 项目列表 ──▶ 项目编辑器（基础信息 + 正文区块编辑器）
                    └── 标签管理
```

## 6. 项目卡片规范

卡片只放"一眼看懂"的信息：

```
[ 封面图片（统一比例，如 16:9 / 3:2）]
项目名称（加粗，单行）
一句话介绍（单行省略）
[Go] [AST] [VS Code]     （技术标签，最多 3-4 个）
★ 推荐                   （推荐标识，可选）
```

**规范**：
- 封面统一比例，避免网格错位。
- 一句话介绍超长省略号截断。
- 标签最多展示 3-4 个，其余省略。
- 悬停轻微放大 / 阴影，提示可点击。

## 7. 视觉基调

| 项 | 建议 |
| --- | --- |
| 风格 | 简洁、克制的现代展示风（参考 Pixiv 的白底 + 内容优先） |
| 主色 | 中性色为主，品牌色做点缀（如深蓝/橙） |
| 字体 | 系统字体栈，标题加粗 |
| 布局 | 卡片网格（响应式：桌面 3-4 列，平板 2 列，移动 1 列） |
| 图片 | 统一比例、懒加载 |

---

## 8. 移动端

前台响应式：卡片单列、搜索框置顶、详情页图片通栏。后台以桌面为主，不做移动端适配（V1）。
