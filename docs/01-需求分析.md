# 大连理工大学实训基地优秀项目展示系统 —— 需求分析

> 版本：V1.0　日期：2026-09-01　评审节点：9 月 8 日需求分析评审
> 技术栈：MySQL + Vue 3 + Go 1.26.x（后续 Redis / Docker / 阿里云）

---

## 1. 引言

### 1.1 编写目的
本文档描述「大连理工大学实训基地优秀项目展示系统」的需求，作为后续原型设计、概要设计、数据库设计、编码与测试的依据。文档面向开发团队、评审教师及项目维护者。

### 1.2 项目背景
实训基地每期会产出大量学生优秀项目，但目前缺少一个统一的展示平台。本项目旨在构建一个 **"项目作品展示系统"**，集中展示优秀项目，供师生浏览、发现、检索和阅读项目详情，并由管理员维护内容。

### 1.3 术语定义

| 术语 | 含义 |
| --- | --- |
| 前台 / 展示站 | 面向访客的浏览端（Vue） |
| 后台 / 管理端 | 面向管理员的维护端（Vue） |
| 项目作品 | 一个完整的展示单元（含封面、介绍、详情正文、成果等） |
| 作品文章 | 项目详情页的正文，由有序的内容区块构成 |

---

## 2. 产品定位

**本系统不是社交平台，而是"项目作品展示平台"。**

核心一句话：

> **打开 → 浏览项目 → 发现项目 → 阅读项目**，30 个项目被当作 **30 件可阅读、可发现的内容作品**，而非 30 条数据库记录。

### 2.1 参考产品的借鉴点

| 参考产品 | 借鉴能力 | 落地到本系统 |
| --- | --- | --- |
| Reddit | 内容流、搜索、信息密度、持续发现 | 首页搜索为一级入口，信息流式浏览 |
| Pixiv | 作品展示、图片权重、作品详情 | 详情页以作品为主角，UI 不抢风头 |
| 小红书 | 卡片式发现、封面驱动、瀑布流/网格 | 项目卡片一眼看懂，封面驱动点击 |

### 2.2 明确的边界（不做）

- ❌ 点赞 / 评论 / 收藏 / 关注
- ❌ 用户主页、社交关系、热榜
- ❌ 用户注册（访客无需登录；仅管理员登录后台）

这些功能会改变产品性质，故明确排除。

## 3. 用户角色

| 角色 | 说明 | 权限 |
| --- | --- | --- |
| 访客 | 所有打开前台的人 | 浏览首页、搜索、查看项目详情 |
| 管理员 | 实训基地内容维护人员 | 登录后台、管理项目、编辑项目文章、管理标签 |

## 4. 功能需求

### 4.1 前台（展示站）

**FR-01 首页（项目社区）**
- 打开即进入内容浏览，而非宣传页。
- 顶部醒目的**中央搜索框**作为全站内容入口。
- 首页展示推荐项目（信息流 / 卡片网格）。

**FR-02 搜索（一级交互）**
- 输入关键词即时出现结果联想（项目名 / 简介 / 技术栈匹配）。
- 点击联想项直接进入项目详情，不经过复杂搜索页。
- 支持按技术栈标签筛选浏览。
- 匹配字段：`Project.Name`、`Project.Description`、`Project.Content`、`Project.TechStack`。

**FR-03 项目卡片**
- 卡片仅含：封面、项目名称、一句话介绍、少量技术标签、推荐标识（★）。
- 用户扫一眼即可判断是否点入。

**FR-04 项目详情（作品文章）**
- 以作品为视觉主角：项目名称、一句话介绍、封面、正文（章节/文本/图片）、成果、项目成员。
- 正文支持多章节与图文混排。
- 返回可继续浏览。

### 4.2 后台（管理端）

**FR-05 管理员登录**
- 账号密码登录，鉴权后进入后台。

**FR-06 项目管理**
- 项目列表（搜索、筛选、排序）。
- 新增 / 编辑 / 删除项目。
- 项目上下架（发布状态管理）。

**FR-07 项目文章编辑**
- 编辑项目基础信息（标题、简介、封面、技术栈、成员、推荐标识）。
- 编辑项目详情正文：按"章节 → 文本 / 图片 / 标题"自由组织区块。
- 上传封面与正文配图。

**FR-08 标签管理**
- 维护技术栈标签，供项目关联与前台筛选。

| 编号 | 用例名 | 角色 | 说明 |

## 5. 数据需求概览

- **项目基础信息**：标题、一句话简介、封面、技术栈、成员、推荐标识、发布时间、状态。
- **项目正文**：有序内容区块（标题 / 文本 / 图片），解耦存储。
- **标签**：技术栈名称，多对多关联项目。
- **管理员**：账号、密码（加密）、创建时间。
- **图片**：V1 阶段存于本地文件目录 `/uploads`（数据库存相对 URL），二期迁移对象存储（OSS），存储层抽象以便解耦迁移、业务代码不变。

## 6. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 首页与详情页秒开；图片做压缩/缓存优化；搜索响应 < 500ms |
| 安全 | 管理员密码加密存储；接口鉴权；防 SQL 注入（参数化查询）；图片上传校验 |
| 可维护性 | 前后端分离；后端分层；统一错误码与响应结构 |
| 可扩展性 | 内容模型与存储层解耦，便于后续上 Redis / Docker / OSS / 云部署 |
| 兼容性 | 适配主流浏览器（Chrome / Edge / Safari）；移动端可响应式浏览 |

## 7. 设计原则（贯穿全站）

1. **搜索即入口**：搜索框是内容第一入口，搜索 → 内容，而非搜索 → 搜索页 → 内容。
2. **作品即主角**：详情页让项目作品本身成为视觉核心。
3. **卡片即判断**：卡片让用户一眼判断是否点击。
4. **内容而非数据**：30 个项目 = 30 篇作品，详情模型按"文章"设计。
5. **弱化后台存在感**：前台沉浸浏览，后台快速编辑，两种体验分离。

---

## 8. 验收标准（V1）

- [ ] 前台首页可浏览推荐项目，搜索框可即时联想并直达详情。
- [ ] 项目详情页正确渲染标题、封面、图文混排正文、成果与成员。
- [ ] 后台可登录，并完成项目的增删改查与上下架。
- [ ] 后台可编辑项目文章（章节/文本/图片区块）。
- [ ] 图片可上传、存储并正确展示。
- [ ] 项目正文内容模型与基础信息解耦，便于后续迁云。
