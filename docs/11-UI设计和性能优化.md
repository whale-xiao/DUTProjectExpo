## 0. 一句话定调

> **前台不是"管理系统的展示面"，而是一间"有节奏的展馆"：界面隐去、滚动成叙事、每个像素为作品服务。**

国际一流内容/作品站与本项目的差距，几乎全部在**减法与节奏**，不在炫技。多数"高级感"改动是打磨层，不必推翻现有 09 架构与设计令牌。

## 1. 国际优秀内容/作品站的共性优点（原则）

来源：Codrops 2026 拆解（Pell Mell / Podium / R—K）与 Awwwards 四奖站 By-Kin 的开发者复盘。

| # | 原则 | 出处要点 |
| --- | --- | --- |
| 1 | **界面要消失**：把 UI 控件删到只剩必要，像翻杂志而不是操作平台 | Pell Mell：多数作品站"干净的网格、筛选、分类，却毫无感觉"；想做成 magazine 而非 directory [Pell Mell](https://tympanus.net/codrops/2026/03/27/pell-mell-crafting-a-visual-exploration-platform-with-editorial-rhythm/) |
| 2 | **底层严格、表层松弛**：看着自由，背后是严格系统；打磨重点在**节奏/间距/留白/内容出现时机** | 同上 |
| 3 | **克制 = 决定删什么**：连续叙事优先于页面块拼贴 | Podium（跑步影像工作室）：从 page-based 转向 sequence-driven，导航/转场/层级都为延续作品节奏服务 [Podium](https://tympanus.net/codrops/2026/06/23/podium-building-a-website-where-running-becomes-storytelling/) |
| 4 | **每个像素挣得位置**：动效系统、性能、工程 craft 决定获奖（Developer Award） | By-Kin：Awwwards Site of the Day ×4，胜在 motion 系统与性能而非截图 [By-Kin 复盘](https://www.hontran.dev/blog/by-kin-case-study-award-winning-website) |
| 5 | **轻量动效**：原生 IntersectionObserver / CSS transition 足够，不引重型动画框架 | Pell Mell / R—K 都用原生 API 做 reveal，动画为节奏与性能让路 [R—K](https://tympanus.net/codrops/2026/04/07/r-k-26-the-thinking-and-code-behind-a-portfolio-led-by-presence/) |

## 2. 2025–2026 全球 UI 趋势速览（取舍表）

> 来自 2026 设计趋势综述（Metabole / MadeGood / Webflow / 中文设计社区）。**注意"适用性取舍"列**——不是每一条都要做。

| 趋势 | 说明 | 本项目适用性取舍 |
| --- | --- | --- |
| 编辑式极简（Editorial Minimalism） | OpenAI/Linear/Stripe 走 barely-there UI，克制本身是信号 | ✅ 主方向，就是 08 基线 |
| 大字号少字体 | 标题 34→60+px，全站 1–2 款字体，靠字重/衬线对位 | ✅ `display` 38px 可上调一档 |
| 色彩收敛 | 非纯白底（近白冷调）、配色 ≤ 3–4 档 | ✅ 已按 tokens 收敛；守住"暖橙只给 ★ 推荐" |
| 微交互（Micro-interactions） | hover/过渡承载"用心"信号，120–260ms | ✅ 已用 tokens；统一成动效令牌文件 |
| 本托布局（Bento Grid） | 日本便当盒式内容模块化网格 | ⚠️ 可选做首页"推荐+分类"混排区，勿全站本托 |
| 暗色模式成默认考量 | 深灰 #121212 而非纯黑，light/dark 并行 | ⚠️ 展示站暗色出氛围；二期做，别用纯黑 |
| 手工感 / 反 AI 同质化 | 细腻纹理、签名插画作差异化 | 🚫 本项目不需要（内容是项目作品，非品牌感营销页） |
| 玻璃拟态 / 霓虹渐变 / 重型 3D | 2026 已退潮、用户看腻 | 🚫 明确不做 |

## 3. 前台 UI 优化清单（逐条含验收标准）

### A. 排版与字阶
| 项 | 做法 | 验收标准 | 成本 |
| --- | --- | --- | --- |
| A1 | 详情页作品名 `display` 由 38px 上调至 48–56px，行高 1.15 | 截图看首屏"作品即主角"，标题在 1080 宽下有力不挤 | 低 |
| A2 | 全站字重纪律：宋体标题 ≤700、无衬线标题 ≤700，不用 900 | 无发虚的粗体字 | 低 |
| A3 | 正文窄列 720px + 行高 1.9 已达标；检查首行缩进/段距一致性 | 详情正文读 2 段无跳脱感 | 低 |

### B. 布局与栅格
| 项 | 做法 | 验收标准 | 成本 |
| --- | --- | --- | --- |
| B1 | 列表页把"分类 chips + 排序"收敛为次级条：常驻只留搜索框，其余折叠成一个"筛选"入口，点开再展开 | 首屏信息流不被打断，筛选可用且可见 | 中 |
| B2 | 首页做"本托混排"试点：大推荐卡（2 格宽）+ 普通卡穿插，而非清一色等宽 | 视觉有层次但网格仍对齐 | 中 |
| B3 | 卡片 hover 封面 1.02 放大已实现；补"整卡阴影 + 上浮 2px"，时间统一 120ms | hover 有"可点"的明确反馈 | 低 |

### C. 动效与叙事
| 项 | 做法 | 验收标准 | 成本 |
| --- | --- | --- | --- |
| C1 | 详情正文块**随滚动轻浮现**：给 BlockRenderer 每个块加 `.reveal`，用 IntersectionObserver 加 `.visible`（translateY 8px→0 + opacity，260ms，不引库） | 滚动到某段它平滑出现；`prefers-reduced-motion` 时全部禁用 | 中 |
| C2 | 章节标题（heading 块）可做轻微左滑入 + 装饰短线的入场，与正文段落区分节奏 | 小节之间有明显"节奏分隔" | 中 |
| C3 | 搜索联想下拉项 hover 已做背景色；补**键盘 ↑↓ 时内容跟随滚动**（activeIndex 项 scrollIntoView） | 长列表键盘操作不丢失焦点 | 低 |

### D. 图片与色彩
| 项 | 做法 | 验收标准 | 成本 |
| --- | --- | --- | --- |
| D1 | 封面统一 3:2 且**真实内容**补齐（替换占位首字） | 首页网格无空占位，第一眼是"作品" | 中 |
| D2 | `<img>` 全部带 `loading="lazy" decoding="async"`（已部分）；补 alt 语义 | Lighthouse 图片项绿灯 | 低 |
| D3 | 暖橙 `--accent` 只用于 ★推荐徽标与强调数字，排查误用 | 截屏数橙点占比 <3% | 低 |
| D4 | （二期）暗色模式：底色用 `#121212` 系深灰而非纯黑，封面仍明亮 | 切换后正文对比度达标 | 高 |

### E. 状态与反馈
| 项 | 做法 | 验收标准 | 成本 |
| --- | --- | --- | --- |
| E1 | 把加载/空/错误/404 四种状态做成**可复用组件**（现散落在各 view） | 各页状态文案/插画一致 | 中 |
| E2 | 列表切分类/排序/搜索时若数据未变则不闪烁（请求结果 diff） | 快速连点不闪骨架屏 | 中 |

## 4. 后台 UI 优化清单（若依精简版已就位）

| 项 | 做法 | 验收标准 | 成本 |
| --- | --- | --- | --- |
| AD1 | Element Plus 改**按需自动导入**（`unplugin-vue-components` + `ElementPlusResolver`） | 主包由 ~877KB 显著下降（见 §5） | 低 |
| AD2 | 项目列表列密处理：封面缩略 40px、隐藏次要列可选"列设置" | 30 条内一屏可扫 | 低 |

| AD4 | 未保存离开提醒（`beforeunload` + 路由守卫） | 误退不丢编辑 | 低 |
| AD5 | 顶栏加"查看前台"入口、面包屑接当前项目名 | 编辑时可一键预览前台 | 低 |

## 5. 前端性能优化清单（"更流畅"专项）

> 目标指标（对齐非功能需求 NFR-01）：首页/详情 **LCP < 1.3s**、**FCP < 1s**、交互无 300ms 卡顿。

### 现状对照（编码期已完成 ✅）
- 路由级懒加载（前台/后台都按页分包）
- 搜索防抖 200ms + AbortController 中断过期请求
- 图片 lazy + async；封面 3:2
- 后台表格/详情正常

### 待办（按收益排序）
| 项 | 做法 | 预期收益 | 成本 |
| --- | --- | --- | --- |
| P1 | Element Plus 按需引入（后台主包 877KB 主要来自全量 element-plus） | 首屏 JS 减 60%+ | 低 |
| P2 | 详情接口数据页面缓存（Pinia）：返回"全部项目"再点开不重拉；浏览过的详情存最近 N 个 | 详情二次打开秒开 | 低 |
| P3 | 列表 store 化：离开列表页返回不重新拉数据、滚动位置保持 | 列表切换 0 网络抖动 | 中 |
| P4 | 图片加宽度参数：上传存原图，前端 `<img srcset>`/后端出 3:2 压缩尺寸（封面 640w/1280w） | 移动端省流量、桌面清晰 | 中 |
| P5 | 打包拆 vendor：`manualChunks` 把 vue/axios 与业务分开；关注 chunk 大小告警 | 缓存命中率提升 | 低 |
| P6 | Lighthouse 基线跑一次存档（`npx lighthouse http://localhost:5173`），每次改动对比 | 性能回归可视化 | 低 |

### 后端配合项（给服务端优化）
- 详情浏览量一期 GET +1 有"刷新重复计数"，二期改 `POST /api/projects/:id/views` + Redis 计数去抖（契约见 09 §4.4）。
- 首页 `/api/home`、详情加 Redis 缓存 key（03/10 已预留），缓存失效点在编辑/上下架。
- 列表 tags 已批量 `IN` 取，复核无 N+1。
