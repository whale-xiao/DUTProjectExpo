## 1. 概述

本系统采用**前后端分离**架构：两个独立的前端工程（展示前台 + 管理后台）通过 HTTP REST API 与一个 Go 后端交互，后端访问 MySQL 数据库。图片 V1 阶段以 BLOB 形式存于数据库，存储层抽象以便后续迁至对象存储。

```
┌────────────────┐   ┌────────────────┐
│  展示前台 Vue3  │   │  管理后台 Vue3  │
│  (访客浏览)     │   │  (内容管理)     │
└───────┬────────┘   └───────┬────────┘
        │      HTTP/JSON     │
        └─────────┬──────────┘
                  ▼
        ┌───────────────────┐
        │   Go 后端 (REST)   │
        │  handler/service/  │
        │  repository        │
        └─────┬─────────┬───┘
              │         │
              ▼         ▼
        ┌─────────┐ ┌──────────────┐
        │  MySQL  │ │ Storage 抽象  │
        │ (数据)  │ │ (DB BLOB→OSS) │
        └─────────┘ └──────────────┘
```

## 3. 后端分层架构

后端遵循 **handler → service → repository** 三层，职责分离、便于测试与替换：

```
router (Gin 路由 + 中间件)
   │
   ▼
handler    —— 解析 HTTP 请求/响应，参数校验，调用 service
   │
   ▼
service    —— 业务逻辑，事务编排，组装数据
   │
   ▼
repository —— 数据访问（GORM），封装 SQL，供 service 调用
   │
   ▼
model      —— 结构体与表映射（User / Project / Section / Tag）
storage    —— 图片存取抽象接口（V1: DB BLOB；后续: OSS）
```

### 3.1 目录结构（后端）

```
backend/
├── main.go                 # 入口：加载配置、初始化 DB、注册路由
├── config/                 # 配置加载（yaml / env）
├── router/                 # 路由与中间件
│   ├── router.go
│   └── middleware/         # JWT 鉴权、CORS、日志、错误处理
├── handler/                # HTTP 处理层
├── service/                # 业务逻辑层
├── repository/             # 数据访问层
├── model/                  # 数据模型 / 表结构
├── storage/                # 图片存储抽象
│   ├── storage.go          # 接口定义
│   └── db_storage.go       # V1: 存 MySQL BLOB
├── dto/                    # 请求/响应结构体
└── pkg/                    # 通用工具（响应、错误码、分页）
```

### 3.2 统一响应与错误码

所有接口返回统一结构：

```json
{
  "code": 0,
  "message": "ok",
  "data": { }
}
```

- `code = 0` 成功；非 0 为业务错误码。
- 错误码集中定义于 `pkg/errcode`，便于前端统一处理。

## 6. 接口设计原则（RESTful）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/projects` | 项目列表（分页、标签筛选、关键词） |
| GET | `/api/projects/:id` | 项目详情（含正文区块） |
| POST | `/api/projects` | 新增项目（管理员） |
| PUT | `/api/projects/:id` | 更新项目 |
| DELETE | `/api/projects/:id` | 删除项目 |
| POST | `/api/auth/login` | 管理员登录 |
| GET | `/api/tags` | 标签列表 |
| POST | `/api/images` | 上传图片 |
| GET | `/api/images/:id` | 读取图片 |

---

## 7. 关键设计决策

1. **内容模型解耦**：项目基础信息（`projects`）与详情正文（`project_sections`）分表存储，后台以"文章区块"组织，避免几十个零散字段。
2. **存储层抽象**：图片经 `storage.Storage` 接口存取，V1 用数据库 BLOB，后续实现 `oss_storage.go` 即可无缝迁移，不改业务代码。
3. **前后端分离**：两个前端工程独立开发部署，后端提供纯 JSON API。
4. **预留扩展**：缓存、容器化、云部署在架构上预留，不在 V1 实现但不受阻。

## 8. 部署架构（后续）

```
用户浏览器
    │
    ▼
Nginx (静态资源 + 反向代理)
    ├── /            → 展示前台静态文件
    ├── /admin       → 管理后台静态文件
    └── /api/*       → Go 后端 (Docker 容器)

                          ▼
                     MySQL (RDS)  +  OSS (图片)
```
