## 1. 概述

数据库存储项目作品内容与后台管理数据，共 5 张业务表。核心设计思想是**"项目基础信息"与"详情正文"解耦**：`projects` 只存卡片一眼可见的字段，`project_sections` 存详情页的有序文章区块。

---

## 2. E-R 模型

```
[users] 1 ──────< 维护 >────── ∞ [projects]

[projects] 1 ────< 包含 >────── ∞ [project_sections]

[projects] ∞ ────< 关联 >────── ∞ [tags]
                (project_tags)

[images] ∞ <──── 引用 ────── [projects.cover_id]
[images] ∞ <──── 引用 ────── [project_sections.image_id]
```

- `projects` ↔ `tags` 为**多对多**，经中间表 `project_tags`。
- `projects` 与 `project_sections` 为**一对多**。
- `images` 被 `projects` 和 `project_sections` 引用（图片独立存储，便于迁云）。

## 3. 表结构

### 3.1 users（管理员）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK, AUTO_INCREMENT | 主键 |
| username | VARCHAR(64) | NOT NULL, UNIQUE | 用户名 |
| password_hash | VARCHAR(255) | NOT NULL | 密码哈希（bcrypt） |
| created_at | DATETIME | NOT NULL | 创建时间 |
| updated_at | DATETIME | NOT NULL | 更新时间 |

### 3.2 projects（项目基础信息）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK, AUTO_INCREMENT | 主键 |
| title | VARCHAR(128) | NOT NULL | 项目名称 |
| slug | VARCHAR(128) | NOT NULL, UNIQUE | 唯一标识（URL 友好） |
| summary | VARCHAR(255) | NOT NULL | 一句话介绍 |
| cover_id | BIGINT UNSIGNED | NULL, FK→images.id | 封面图片 |
| tech_stack | VARCHAR(255) | NULL | 技术栈摘要（冗余，如 "Go,AST,VS Code"） |
| members | VARCHAR(255) | NULL | 项目成员（逗号分隔） |
| recommended | TINYINT(1) | NOT NULL DEFAULT 0 | 是否推荐（首页展示） |
| status | TINYINT | NOT NULL DEFAULT 0 | 0草稿 / 1已发布 / 2已下架 |
| created_at | DATETIME | NOT NULL | 创建时间 |
| updated_at | DATETIME | NOT NULL | 更新时间 |

### 3.3 project_sections（详情正文区块）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK, AUTO_INCREMENT | 主键 |
| project_id | BIGINT UNSIGNED | NOT NULL, FK→projects.id | 所属项目 |
| sort | INT | NOT NULL DEFAULT 0 | 排序序号 |
| type | TINYINT | NOT NULL | 1标题 / 2文本 / 3图片 |
| content | TEXT | NULL | 文本内容（type=1/2） |
| image_id | BIGINT UNSIGNED | NULL, FK→images.id | 图片（type=3） |
| created_at | DATETIME | NOT NULL | 创建时间 |

> 解耦说明：正文用"区块"而非几十个固定字段，管理员可自由组织章节；`type` 决定前端渲染方式。

### 3.4 tags（技术栈标签）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK, AUTO_INCREMENT | 主键 |
| name | VARCHAR(64) | NOT NULL, UNIQUE | 标签名（如 Go、Vue） |
| created_at | DATETIME | NOT NULL | 创建时间 |

### 3.5 project_tags（项目-标签关联）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| project_id | BIGINT UNSIGNED | PK, FK→projects.id | 项目 |
| tag_id | BIGINT UNSIGNED | PK, FK→tags.id | 标签 |

> 联合主键保证同一项目不重复关联同一标签。

### 3.6 images（图片，V1 存 DB）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK, AUTO_INCREMENT | 主键 |
| data | MEDIUMBLOB | NOT NULL | 图片二进制（V1） |
| mime | VARCHAR(64) | NOT NULL | MIME 类型（image/png 等） |
| size | INT UNSIGNED | NOT NULL | 字节大小 |
| created_at | DATETIME | NOT NULL | 上传时间 |

> V1 图片以 BLOB 存数据库；后续迁移 OSS 时，本表可保留元数据、`data` 替换为 `url`，由存储层抽象完成，业务代码不变。

## 4. 索引设计

| 表 | 索引 | 目的 |
| --- | --- | --- |
| projects | UNIQUE(slug) | 唯一访问标识 |
| projects | INDEX(status, recommended) | 首页推荐查询 |
| projects | INDEX(title) | 标题搜索 |
| project_sections | INDEX(project_id, sort) | 按项目取有序正文 |
| tags | UNIQUE(name) | 标签唯一 |
| project_tags | PK(project_id, tag_id) | 关联查询 |

---

## 5. 约束与关系

- 所有表 `utf8mb4`，支持中文与 emoji。
- 外键：`cover_id` / `image_id` → `images.id`（`ON DELETE SET NULL`）；`project_sections.project_id` → `projects.id`（`ON DELETE CASCADE`，删项目连带删正文）。
- 删除项目时，其标签关联与正文一并清理。

---

## 6. 核心查询示例

```sql
-- 首页推荐项目（含封面、标签）
SELECT p.id, p.title, p.summary, p.recommended,
       GROUP_CONCAT(t.name) AS tags
FROM projects p
LEFT JOIN project_tags pt ON pt.project_id = p.id
LEFT JOIN tags t ON t.id = pt.tag_id
WHERE p.status = 1 AND p.recommended = 1
GROUP BY p.id
ORDER BY p.created_at DESC;

-- 项目详情正文（有序）
SELECT sort, type, content, image_id
FROM project_sections
WHERE project_id = ?
ORDER BY sort ASC;

-- 关键词搜索（标题/简介/技术栈）
SELECT * FROM projects
WHERE status = 1
  AND (title LIKE ? OR summary LIKE ? OR tech_stack LIKE ?);
```
