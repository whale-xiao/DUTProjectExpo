# 前台影院化改造方案（首页 Hero + 详情页电影化）

> 版本：V1.0 ｜ 日期：2026-09-14 ｜ 状态：**待评审**
> 范围：**仅 `frontend-showcase/`**，后端零改动
> 关系：本方案**取代** `09-前台设计方案.md` 的 §5.1（首页）与 §5.4（详情页）两节；`09` 其余章节（§3 搜索、§4 接口、§6 架构）**继续有效**。

## 0. 一句话概括

在**不改变"白墙展馆"整体基调**的前提下，给首页和详情页各加一个**影院式头图区（cinematic hero）**：
首页头图 = 主推作品的大幅剧照 + 暗色遮罩 + 叠字标题；
详情页头图 = 作品通栏大图 + 下方"左资料卡 / 右正文"的电影资料页布局。

**主体仍是浅色**——只有头图区域是暗的。这是"影院感"与既有设计基线之间代价最小的结合点。

## 3. 设计令牌扩展（`styles/tokens.css`）

**纯新增，不修改任何既有变量**，因此对未改动的页面（列表页等）零影响。

```css
:root {
  /* —— 影院头图专用（仅 hero / detail-header 区域使用）—— */
  --hero-h: clamp(420px, 48vh, 540px);      /* 头图高度：随视口伸缩 */
  --hero-h-sm: clamp(300px, 40vh, 380px);   /* 移动端口径 */
  --r-xl: 20px;

  --veil: rgba(8, 12, 20, 0.58);            /* 基础遮罩 */
  --veil-strong: rgba(8, 12, 20, 0.78);     /* 文字所在区加强 */
  --cinema-ink: #ffffff;
  --cinema-sub: rgba(255, 255, 255, 0.80);
  --cinema-line: rgba(255, 255, 255, 0.22);
  --cinema-chip: rgba(255, 255, 255, 0.12);

  --shadow-hero: 0 24px 60px rgba(8, 12, 20, 0.28);
  --ease-out: cubic-bezier(0.16, 1, 0.3, 1);  /* 头图入场用，比 --ease 更"沉" */
}
```

**遮罩公式**（保证白色文字对比度 ≥ 4.5:1，满足 WCAG AA）：

```css
background:
  linear-gradient(to top,  var(--veil-strong) 0%, transparent 55%),
  linear-gradient(to right, var(--veil)        0%, transparent 62%);
```

> 文字只压在左下角，因此用"下→上"与"左→右"两道渐变叠加；右上区域保持图片原貌，作为视觉呼吸口。

### 4.3 搜索框位置（关键决策）

**搜索框保持在头图下缘上浮、与头图重叠 28px**，理由：

- `09` §2 原则 1 明确"**搜索是第一条路，不是附属品**"——不能因为加了头图就把搜索挤下去。
- 搜索框压在明暗交界线上，浅色胶囊 + 阴影，两侧对比都强，视觉上反而更突出。
- 头图高 420–540px，搜索框落在首屏 600px 内，**仍然在首屏可见**，未破坏"搜索是一级入口"。

> 备选方案（不推荐）：搜索框放在头图**上方**。会削弱影院感，且头图被推到首屏之外。

### 4.4 ⚠️ 核心约束：现有封面只有 1200 × 800

实测 `backend/uploads/` 全部封面均为 **1200 × 800（3:2）**。全屏通栏的后果：

| 视口宽度 | 放大倍数 | 观感 |
| --- | --- | --- |
| 1280px | 1.07× | 几乎无损 |
| 1440px | 1.20× | 可接受（暗色遮罩会掩盖软化） |
| 1920px | 1.60× | **明显发虚** |
| 2560px | 2.13× | 不可接受 |

**处理方式（三选一，本方案建议 D1 + D3 组合）**：

| # | 做法 | 代价 |
| --- | --- | --- |
| D1 | **接受放大**，靠遮罩 + 轻微暗化掩盖软化；头图高 ≤ 540px，不做 4K 友好 | 大屏略软，可接受 |
| D2 | 头图**限宽 1180px 居中**（与 `--content-max` 一致），1:1 像素不放大 | 失去"通栏"影院感 |
| D3 | **后续上传封面改用 1920 × 1080** | 需改 `docs/09` 规格 + 重传已有 30 张 |

**建议：D1 立即可做，同时把 D3 写进待办**（30 张图重传成本可控，越早定越好）。

补充手段：头图允许 `filter: saturate(1.04) contrast(1.03)` 轻微提神；**不要**用 `blur()` 打底再叠锐图（多一层绘制，得不偿失）。

### 4.8 满屏首屏（2026-09-14 追加）

**要求**：进入首页时，最上面几个主推作品的图片**占满整屏**；榜单、分类等板块滚动后才出现。
其余效果一律不动。

**做法**

| 项 | 值 |
| --- | --- |
| 首屏高度 | `--hero-h-screen: calc(100dvh - var(--nav-h))`，不支持 `dvh` 时回退 `100vh` |
| 导航高度 | 新增 `--nav-h: 56px` 令牌（原写死在 `App.vue` 的 `height: 56px`，现两处共用，避免各写一个数） |
| 移动端 | 同样满屏；`dvh` 可用时自动避开地址栏收放引起的整屏跳动 |
| 详情页头图 | **不变**，仍用 `--hero-h`（中等高度） |

**为什么首屏只剩图片**：`--hero-h-screen` 恰好等于「视口高 − 导航高」，所以头图下边缘正好落在折线上；
下方 `search-dock` 靠 `-28px` 负边距探出 28px，充当「下面还有内容」的提示；其余板块全在折线以下，
由 §7 的滚动显现负责浮现。

**实测验证**（无头 Chrome，视口 1440×{900, 1200, 2000, 3200}）：
折线以下的 15 个 `v-reveal` 元素**在四种视口下均未显现**（`class` 属性中 `is-revealed` 计数为 0），
即首屏确实只有头图。

> ⚠️ **副作用：1200×800 封面这个软肋被放大了。**
> 原头图 540px 高时，1200px 宽的图在 1440 视口只放大 1.2×，尚可接受；
> 满屏后高度可达 1000px 以上，同一张图被拉伸得更明显。

**封面规格已定案（2026-09-14）**：`1200×800` → **`1920×1280`（保持 3:2）**，见 `09` §5 的「封面尺寸规格」。
已有 1200×800 的图可继续使用，只是大屏头图会偏软。

### 4.9 导航嵌入头图（2026-09-14 追加，经两轮调整）

**要求演变**

1. 先要求「删掉站名与『全部项目』字样、以及那条空白行」→ 曾**整块移除**顶部导航
2. 再要求「可以加导航，但不要单独留一整空白行，把白色导航文字嵌入图片中」→ **恢复导航，改为覆盖在头图上**

**最终做法**：导航保留两种形态，按路由切换（`App.vue`）：

| 页面 | 形态 | 样式 |
| --- | --- | --- |
| 首页 | **overlay：嵌进头图顶部** | `position: absolute; top: 0`；透明底、无下边框、白字；品牌图标改半透明白 |
| 其余页 | 常规行 | 浅色底 + hairline 下边框，行高 `--nav-h: 56px` |

**为什么用 `absolute` 而不是 `fixed`**：跟着头图一起滚走。若用 `fixed`，滚动之后它会悬空压在浅色内容上，
白字会直接看不见。

**配套改动**

| 令牌 | 变化 | 原因 |
| --- | --- | --- |
| `--hero-h-screen` | 改回**不减导航高度**（`100vh` / `100dvh`） | 导航既浮在图上，就不该占高度 |
| `--veil-grad` | **增加顶部一道渐变** `to bottom, var(--veil) 0%, transparent 20%` | 否则白字直接压图片顶部对比度不够；顺带也改善了详情页「返回」按钮的可读性 |
| `--nav-h` | 恢复 `56px` | 供非首页的常规导航行使用 |

**实测**（1440×900）：

| 检查 | 首页 | 列表页 |
| --- | --- | --- |
| `class` | `site-nav overlay` | `site-nav` |
| 「全部项目」入口 | 1 个 | 2 个 |
| 折线以下 `v-reveal` 元素 `is-revealed` 计数 | **0** | — |

即：**首屏仍然只有图片**，导航浮在图上而不占一行高度。

### 4.10 搜索框并入导航行（2026-09-14 追加）

> **本节取代 §4.3**（原方案是「搜索框上浮、与头图下缘重叠 28px」，现已作废）。

**要求**：搜索框也用同样方式放到导航同一行。

**做法**：首页导航行变为三栏 `[站名] [搜索框] [全部项目]`，搜索框与导航同为 overlay 形态；
`HomeView` 里原来单独占一条、上浮重叠头图下缘的 `.search-dock` **整块移除**。

| 项 | 实现 |
| --- | --- |
| 位置 | `App.vue` 的 `.nav-search`（仅首页渲染），`flex: 1; max-width: 520px` |
| 形态 | `SearchBox` 新增 `variant="glass"`：半透明毛玻璃、白字、高 40px、圆角胶囊 |
| 联想下拉 | **仍用不透明的 `--surface`**，保证压在图片上也读得清 |
| 清理 | `HomeView` 移除 `SearchBox` 导入、`useRouter`、`goDetail`/`goSearch`、`.search-dock` 样式 |

**为什么不复用已有的 `size="inline"`**：`inline` 已被列表页（`/projects` 页头）使用，
直接改它的高度会连带改动列表页。故新增 `variant` 维度，与 `size` 正交。

**实测**（1440×900）

| 检查 | 结果 |
| --- | --- |
| nav 的 class | `site-nav overlay` |
| 搜索框 | `searchbox inline glass`，位于 `<header>` 内 |
| 结构顺序 | `header → main → section.hero` |
| 折线以下 `v-reveal` 元素 `is-revealed` 计数 | **0**（首屏仍只有图片） |
| 独立搜索区残留 | 0 |

> ⚠️ **副作用**：原「搜索框上浮重叠头图下缘 28px」那个**滚动提示也随之消失**。
> 首屏现在是一整屏图片、底部没有任何内容探出。若担心用户停在首屏不动，
> 需要另加滚动提示（如底部中央的向下箭头）——目前**未做**，是已知缺口。

### 5.5 剧照（`image` 内容块）的电影化处理

> **实施修正（2026-09-14）**：原计划把剧照放宽到 860px 突破正文列，但两栏布局中正文列本身
> 就是 720px，向外突破会溢出容器（1024px 视口下尤其明显）。故**改为在正文列内处理**：

- 宽度保持 `max-width: 100%`、`max-height: 540px`，**不裁剪**（`object-fit: cover` 会破坏作者原图构图，不用）。
- 加一道极细内描边 `inset 0 0 0 1px rgba(30,36,51,.06)`——浅色剧照压在浅色纸面上时，给一个若有若无的边界。
- `figcaption` 改为**左对齐小字**（原为居中），更接近剧照说明的语感。
- 首屏以外的剧照保持 `loading="lazy"`；**只有头图**用 `fetchpriority="high"`。

## 7. 编辑节奏（滚动显现 + 动效语言）

> 参考 [Pell Mell — Codrops](https://tympanus.net/codrops/2026/03/27/pell-mell-crafting-a-visual-exploration-platform-with-editorial-rhythm/)。
> 它的立意与本项目一致：**「不再做一个干净的网格目录，而是把浏览作品做成翻杂志」**。
> 本方案取其中两件事：**滚动显现的节奏**、**统一的手感**。

### 7.1 ⚠️ 修正：IntersectionObserver ≠ scroll 监听

本方案 §10 原本写的是「**不注册 scroll 监听**」。这句本身没错，但当时被理解成
「什么滚动效果都不做」，把 Pell Mell 的核心一并排除了——**这是我表述过窄，此处更正**。

两者的开销差一个量级：

| 方式 | 触发频率 | 执行位置 | 长列表后果 |
| --- | --- | --- | --- |
| `window.addEventListener('scroll')` | **每帧** | 主线程 | 容易掉帧 |
| `IntersectionObserver` | **元素进出视口各一次** | 合成线程回调 | 无累积开销 |

结论：**`scroll` 事件仍然禁止；`IntersectionObserver` 完全可用**——Pell Mell 用的正是后者。

### 7.2 实现（`src/directives/reveal.js`）

全局指令 `v-reveal`：

```html
<div v-reveal>         <!-- 进入视口时浮现 -->
<div v-reveal="120">   <!-- 延迟 120ms 浮现（错开用） -->
```

| 设计点 | 做法 | 理由 |
| --- | --- | --- |
| 观察器实例 | **全站共用一个** `IntersectionObserver` | 避免每个元素各建一个 |
| 一次性 | 显现后立即 `unobserve` | 滚动再久也不累积观察开销 |
| 触发时机 | `threshold: 0.1` + `rootMargin: 0px 0px -40px 0px` | 露头 10% 且越过视口下缘 40px，避免「刚碰到边就弹」 |
| 错开 | 网格卡片 `Math.min(i,5)*70`；分类行 `i*60` | 单批错开、封顶，避免长列表末尾干等 |

**三道兜底，保证内容绝不会卡在隐藏态：**

1. `.reveal` 类由指令（JS）添加 → **JS 整体失效时压根不加类，内容正常可见**
2. `prefers-reduced-motion` 或不支持 `IntersectionObserver` → 直接标记已显现，不注册观察
3. `global.css` 再加一道 `@media (prefers-reduced-motion: reduce)` 强制可见

**实测验证**（无头 Chrome，同一页面不同视口高度）：

| 窗口高度 | 已显现元素数 |
| --- | --- |
| 900 | 2 |
| 1600 | 3 |
| 3000 | 10 |
| 5000 | 16 |

随视口高度单调递增 = 进入视口的内容才显现，符合预期。错开延迟实测到 `60/70/120/140/180/210/280ms`。

### 7.3 动效语言统一（`tokens.css`）

此前各组件分别写 `0.12s` / `0.18s` / `0.2s`，观感是拼凑的。Pell Mell 说 hover 要
「简单但**持续**」——重点在一致。新增 4 个令牌，**新代码一律用令牌，不再写数字**：

| 令牌 | 值 | 用在哪 |
| --- | --- | --- |
| `--dur-fast` | `0.16s` | 指针悬停等微反馈（导航、搜索框、榜单行高亮、箭头淡入） |
| `--dur-base` | `0.28s` | 卡片抬升与图片缩放、按钮状态、轮播圆点 |
| `--dur-slide` | `0.6s` | 头图轮播换帧 |
| `--dur-slow` | `0.7s` | 滚动显现 |

统一范围共 7 个文件：`ProjectCard`、`CategoryRow`、`RankBoard`、`HeroBanner`、
`DetailHero`、`SearchBox`、`App.vue`。

### 7.4 两条实现约束（防止写错）

1. **`v-reveal` 绝不能加在 `position: sticky` 元素的祖先上** —— `transform` 会让
   sticky 失效。故详情页的 `.body-grid` 与 `MetaCard` 均不加显现。
2. **`v-reveal` 挂在「根部为 v-if/v-else 链」的组件上会告警**（如 `BlockRenderer`），
   需改用外层 `<div>` 承载。见 `ProjectDetailView.vue` 内的注释。

## 10. 性能与可访问性（对齐 `11-UI设计和性能优化.md`）

**性能**

- 头图是页面的 **LCP 元素**：`fetchpriority="high"`、`decoding="async"`，**不加 `loading="lazy"`**；其余图片保持 lazy。
- 遮罩是纯 CSS 渐变，**零额外请求**。
- **不使用** `background-attachment: fixed`（移动端卡顿）；**不注册 `scroll` 事件监听**；视差一律不做。
  —— 注意区分：滚动显现用的是 `IntersectionObserver`（合成线程回调、一次性），**不在此禁令内**，见 §7.1。
- hover 仅动 `transform` / `opacity`（合成层友好），不动 `box-shadow` 之外的布局属性。
- 滚动显现的观察器全站共用一个，且元素显现后立即 `unobserve`，不随页面长度累积开销。
- 详情页资料卡用 `position: sticky`（CSS 原生），无 JS。

**可访问性**

- 白字压在图上，遮罩公式已保证对比度 ≥ 4.5:1；**标题区必须落在两道渐变覆盖范围内**。
- 头图 `<img>` 带 `alt`（作品名）；纯装饰的兜底渐变容器 `aria-hidden="true"`。
- 「返回」按钮是真实 `<button>`，保留 `:focus-visible` 描边（`global.css` 已有）。
- 头图的入场动画在 `@media (prefers-reduced-motion: reduce)` 下禁用。
