## 4. Git 分支规范

采用简化 Git Flow：

```
main          —— 稳定发布分支（通过评审的代码）
  └── dev     —— 日常集成分支
       ├── feat/xxx   —— 功能分支
       ├── fix/xxx    —— 修复分支
       └── docs/xxx   —— 文档分支
```

**规则**：
- 功能从 `dev` 切分支，完成后合并回 `dev`。
- 关键节点（评审前）`dev` 合并到 `main` 并打 tag（如 `v1.0`）。
- 禁止直接向 `main` 提交。

## 5. 提交规范（Commit Message）

采用约定式提交：

```
<type>(<scope>): <subject>

type: feat / fix / docs / style / refactor / test / chore
```

示例：

```
feat(backend): 新增项目列表查询接口
fix(frontend): 修复搜索联想防抖失效
docs(db): 补充 project_sections 表设计
```

- `subject` 用中文简洁描述，一句一行。
- 一次提交只做一件事。

## 6. 编码规范

### 6.1 Go

- 遵循官方 `gofmt` 格式化，提交前执行 `gofmt -w .`。
- 命名：导出符号驼峰（`GetProjects`），包名小写单数。
- 错误处理：显式 `if err != nil` 返回，不吞异常。
- 分层：handler 不直接写 SQL，经 service → repository。
- 配置与密钥不硬编码，走环境变量。

### 6.2 Vue

- 组件名帕斯卡命名，文件与组件同名。
- 逻辑用 `<script setup>`。
- 样式局部作用域 `scoped`，公共样式放全局。
- 接口调用统一封装在 `api/`，不在组件内散写 axios。

### 6.3 通用

- 统一缩进、统一换行（LF）、文件末尾留空行。
- 中文注释解释"为什么"，不解释"是什么"。

## 7. 代码评审要点

合并到 `dev` 前，由另一名成员评审：

- [ ] 能否通过编译 / 启动无报错
- [ ] 是否符合分层与命名规范
- [ ] 是否存在 SQL 注入 / 未鉴权接口
- [ ] 是否遗漏异常处理
- [ ] 是否通过 `gofmt` / lint
