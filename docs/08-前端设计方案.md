## 1. 设计目标与原则

### 1.1 一句话定位

> 前台是**一面"留白展馆墙"**：30 件学生作品是展品，界面退到幕后，让人把注意力交给封面与正文；
> 后台是**一间"编辑工作台"**：同一套视觉语言，但把密度、效率、确定性放第一位。

### 1.2 设计原则（前台 → 后台连续谱）

| # | 原则 | 前台落地 | 后台落地 |
| --- | --- | --- | --- |
| 1 | 作品登台，界面隐身 | 白底高留白；卡片弱阴影；封面占比最大 | 界面服务于"编辑这篇作品文章"，不做装饰 |
| 2 | 搜索即入口 | 首页中央搜索，输入即时联想、直达详情 | 列表顶部常驻搜索 |
| 3 | 卡片一眼可判 | 封面 + 标题 + 一句话 + 少量标签，信息到顶为止 | 列表行含状态/推荐/更新时间，供批量判断 |
| 4 | 沉浸 vs 高效 | 阅读用宋体正文、大图通栏、长行宽 | 一律无衬线、紧凑表格、键盘可达 |
| 5 | 少即是多 | 一个页面只突出一个动作/一个视觉主角 | 危险操作都要二次确认，反馈即时 |

### 1.3 借鉴与不借鉴

| 参考 | 借鉴 | 明确不借鉴 |
| --- | --- | --- |
| Pixiv | 白底、图片权重、详情以作品为主角 | 其社区感、热榜 |
| 小红书 | 封面驱动的卡片网格、一眼判断 | 瀑布流拼接、红底高饱和 |
| Reddit | 首页即内容、搜索为一级入口 | 文字密度、信息噪音 |
| 校 VI | 学府蓝作品牌锚色 | 校园宣传页的横幅、大图轮播 |

## 2. 视觉方向

- 整体气质：**克制的院校级作品展**——"白纸般干净，但每一张封面都有力"。参考面向"作品"而非"营销"的当代学院展馆网页。
- 前台用色温偏冷的近白（不偏米黄），呼应"屏幕上的白墙"；冷灰蓝承担全部结构线，暖橙只做极小面积点缀。
- 排版双重性格：**交互文字用无衬线（清晰、中性），长文正文与作品名用宋体系衬线（阅读感、作品感）**。这正是"30 件可阅读的作品文章"的排版转译——逛展时，展品名与展签是庄重的，操作按钮是安静的。
- 记忆点（只留一处）：**封面即主角**。首页、卡片、详情首屏都不做花哨开场，封面的大面积与统一比例本身就是视觉识别。
- 反馈动效 > 观赏动效：允许的动效几乎都回答用户动作（展开、确认、进入详情），页面加载不堆砌入场动画。

## 3. 设计令牌（Design Tokens）

### 3.1 色彩

> ⚠️ `brand` 一列以"学府蓝"定位，**正式颜色请在编码前从校 VI 手册取值替换**，其余中性色不受影响。

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#F7F8FB` | 页面画布（极浅冷蓝白） |
| `--surface` | `#FFFFFF` | 卡片、浮层、输入框底 |
| `--hairline` | `#E6E9F0` | 分隔线、描边（一律 1px） |
| `--ink` | `#1E2433` | 主文字（藏青近黑） |
| `--sub` | `#5A6478` | 次要文字、一句话简介 |
| `--muted` | `#A7B0C0` | 占位符、禁用、时间戳 |
| `--brand` | `#0D4A8E` | 链接、选中、主按钮、当前导航 |
| `--brand-deep` | `#08345F` | brand 的 hover / 按下、登录背景 |
| `--brand-soft` | `#E4EEF7` | brand 的浅底 tint（选中行、联想高亮） |
| `--accent` | `#E0700A` | 极少量暖橙：★推荐徽标、强调数字 |
| `--danger` | `#C0392B` | 删除、错误（后台） |
| `--ok` | `#1E7D46` | 成功、已发布（后台） |

**使用规则**
- 暖橙面积占比建议 < 3%，绝不用作大块背景或渐变，避免喧宾夺主。
- 文字层级只用 ink / sub / muted 三档，不做更多灰色档。
- 对比度：正文 on white / bg ≥ 7:1；`sub` 仅用于非关键文字；链接 on white 用 `brand`，hover 用 `brand-deep`。

### 3.2 字体

**前台（展示站）**
| 用途 | 字体 | 说明 |
| --- | --- | --- |
| UI / 卡片 / 导航 | 系统无衬线栈 `system-ui, "PingFang SC","HarmonyOS Sans","Microsoft YaHei",sans-serif` | 数字与拉丁推荐叠 `Inter`（可 npm 引入） |
| 作品名/章节标题 | 宋体系 `"Songti SC","Noto Serif SC","Source Han Serif SC",serif` | 语义"作品/文章"，标题加粗更庄重 |
| 详情正文 | 同上宋体系，行高 1.9+ | 面向阅读 |

**后台（管理端）**
- 一律系统无衬线；Element Plus 默认字体即可，`--el-font-family` 覆写为同一无衬线栈。

**字阶（前台）**
| 令牌 | 大小/字重 | 字族 | 用途 |
| --- | --- | --- | --- |
| `display` | 34px / 700 | 宋 | 详情页作品名 |
| `h-title` | 22px / 700 | 宋 | 正文"章节标题"区块 |
| `h-page` | 20px / 700 | 无衬线 | 页面大标题（全部项目等） |
| `body` | 16px / 400 | 无衬线 | 卡片、导航正文 |
| `article` | 17px / 400 | 宋 | 详情长文本，行高 1.9，字距 +0.02em |
| `caption` | 14px / 400 | 无衬线 | 一句话简介、时间戳 |
| `label` | 12px / 500 | 无衬线 | 标签 Tag 内文字 |

- 无衬线标题字重最高 700，不用 900（中文无衬线伪造超粗会发虚）。
- 中文正文单行建议 ≤ 30 字；详情正文容器最大宽 ≈ 720px。

### 3.3 间距 / 圆角 / 阴影

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| 间距基数 | 4px 递增（4/8/12/16/24/32/48） | 全站统一 |
| 卡片内边距 | 前台 16px；后台行高 48px 紧凑 | — |
| `--r-sm` | 6px | 标签、按钮小件 |
| `--r-md` | 10px | 卡片、输入框 |
| `--r-lg` | 14px | 搜索大框、浮层 |
| 圆角纪律 | 一层元素一个圆角即可，禁止层层都圆 | 参考卡体系翻车点 |
| 阴影 | 前台卡片 `0 1px 2px rgba(30,36,51,.06)`（仅 hover 提到 `0 6px 16px rgba(30,36,51,.10)`） | 后台浮层 `0 8px 24px rgba(30,36,51,.14)` |

### 3.4 动效

| 令牌 | 值 |
| --- | --- |
| 时长 | 快 `120ms`（hover/active）· 中 `200ms`（状态切换）· 进入 `260ms` |
| 缓动 | `cubic-bezier(.2,.6,.25,1)` |
| 原则 | 只动"回答动作"的属性（展开高度、选中色、出现/消失）；不做滚动入场动画堆叠；尊重 `prefers-reduced-motion` 时全部转 0ms/无位移 |

## 4. 布局与栅格

### 4.1 前台

- 最大内容宽 **1180px**，导航与页脚同宽居中。
- 卡片网格：桌面 3 列、平板 2 列、手机 1 列；断点 `≥1024 / 640–1023 / <640`。
- 封面比例 **统一 3:2**（见 §5 封面规范），列间距 24px，行间距 32px。
- 详情页正文列宽 720px 居中；封面大图可在内容宽内通栏（≤1180px），正文再收窄到 720px——形成"宽图 → 窄文"的阅读节奏。

### 4.2 后台

- 桌面布局：左侧固定窄导航（图标+文字，220px），右侧内容区；不做移动端适配（V1，遵循 `05-UI设计` §8）。
- 主操作（新增/发布）恒在右上内容头，列表与编辑器各自横向不溢出。

## 5. 通用组件规范（跨两端的同一套语义）

> 命名沿用基本架构文档目录：前台 `components/`、后台 Element Plus 之上做薄封装，**两端的"动作词"与"反馈词"必须一致**（发布 → 已发布；删除需确认）。

### 5.1 按钮
| 层 | 前台 | 后台 |
| --- | --- | --- |
| 主按钮 | brand 底 + 白字，`发布/搜索/保存` | 同主语义 |
| 次按钮 | hairline 描边 + ink 文字 | Element `default` |
| 文字按钮 | ink/链接 | Element `text` |
| 危险按钮 | 仅删除场景，danger | Element `danger` |
- 按钮文字用**动词 + 结果对象**："保存项目"、"发布"，反馈 toast 同词（"已发布"）。
- 触控目标 ≥ 40px。

### 5.2 标签 Tag（技术栈）
- 浅色描边胶囊：`1px solid hairline`、`bg #F7F8FB`、`caption` 字号、圆角 6px、文字 `sub`。
- 前台展示最多 3 个，溢出收起成 `+N`；后台 tags 用完整可删胶囊。
- 语义色 tag（发布/草稿/下架）仅在后台使用：ok 绿 / muted 灰 / brand-deep 深蓝。

### 5.3 项目卡片（核心组件）
```
┌────────────────────┐
│   [封面 3:2]   ★推荐 │   ← ★ = recommended，右上 12px 暖橙徽标
├────────────────────┤
│ 项目名称（单行加粗） │
│ 一句话介绍（单行省略）│
│ [Go] [AST] [VS]     │   ← tag 最多 3
└────────────────────┘
```
- 封面 hover：轻微放大 1.02 + 阴影加深（120ms），提示可点。
- 无封面时占位：浅灰底 + 项目名首字（保证网格不塌）。

### 5.4 封面 / 图片
- 统一上传校验：仅 `image/png, jpeg, webp`，前端预览 `URL.createObjectURL`。
- V1 图片以 **BLOB** 存储，前端用一个封装 `imageUrl(id)` → `{VITE_API_BASE_URL}/api/images/{id}` 直接做 `<img :src>`；**不把二进制拖进业务状态**，接口失败显示占位图与可重试。
- 所有 `<img>` 必填 `alt`（图片区块无描述时写项目名+"配图"）。

### 5.5 五种页面状态（前台/后台通用）
| 状态 | 呈现 |
| --- | --- |
| 加载 | 前台卡片网格用骨架屏（灰块占位）；详情用段落骨架；后台列表 loading 态 |
| 空 | 明确一句话 + 动作：搜索无结果 →"没有匹配「xx」的项目，换个关键词试试"；后台列表空 →"还没有项目，先新增一篇" |
| 错误 | 页面级错误块，含重试按钮；接口统一错误码解析后给可读文案 |
| 404 | 详情无此项目 →"这篇作品不存在或已下架"+ 返回全部项目 |
| 请求中（提交） | 按钮 loading，禁止重复提交 |

### 5.6 反馈 Toast / 二次确认
- 成功/失败用右上角 toast，同动作动词（§5.1）。
- 删除、下架、覆盖正文这类不可逆或大范围操作一律 `Dialog` 二次确认；确认按钮沿用"动词 + 结果"。

## 6. 前台页面设计（展示站）

### 6.1 首页 `/`（FR-01、UC-01）
| 区块 | 设计 |
| --- | --- |
| 顶部导航 | 极轻：左"优秀项目"文字标（brand），右"全部项目"文字链接；bg 同画布、无盒装感 |
| 中央搜索 | 宽 560px 居中、圆角 14px、聚焦描边变 brand；输入防抖 200ms 即时联想 |
| 联想下拉 | 卡片列表（封面小图 + 名称 + 一句简介截断），命中关键词高亮用 `brand-soft` 底；Esc 关闭、方向键可选中 |
| 推荐区标题 | "推荐项目"（h-page，无衬线 20px），不带眉毛标签/序号 |
| 卡片网格 | §5.3 组件，3/2/1 响应式；数据来自 `GET /api/projects?recommended=true` |

**首页即为内容**：不做巨型 hero。顶部一行导航后即进入搜索与信息流，符合"打开即浏览"。

### 6.2 全部项目 `/projects`（FR-02 标签筛选、UC-04）
- 页头：标题"全部项目" + 右侧**标签筛选条**（横向可滚动胶囊组，"全部" + 各 tech tag，单选即刷）。
- 数据：`GET /api/projects?tag_id=&page=&page_size=`；分页用"加载更多"（按钮居中）更贴浏览节奏。
- 结果数提示：命中数量，供判断。

### 6.3 项目详情 `/project/:slug`（FR-04、UC-03）

> ⚠️ 契约项：05 文档路由用 `slug`，04 接口却是 `GET /api/projects/:id`。**V1 建议后端支持 `GET /api/projects/by-slug/:slug`**（或详情接口允许 slug 解析），编码前在接口对齐时定案。

首屏自上而下：
1. 面包屑/返回：`← 全部项目`（文字链接，回上一浏览位置而非强制首页）。
2. 作品名：**display 级宋体 34px**（视觉主角之一）。
3. 一句话简介：`sub` caption 级，居中读感放宽到 640px。
4. 元信息行：tech tags（最多不限，这里可全量）+ 成员 + 发布时间（`muted` caption）。
5. 封面大图（1180px 通栏）。
6. **正文区块**：按 `project_sections.sort` 顺序渲染——
   - `type=1 标题` → `h-title` 宋体，上下留白 32px；
   - `type=2 文本` → `article` 级 17px 宋体正文，行高 1.9，720px 列宽；
   - `type=3 图片` → 区块图片最多宽 860px 居中，`loading="lazy"`，点击可看大图。
   - 区块间距 24px，区块内不画分割线（区块顺序本身即结构信息）。
7. 页尾：`返回全部项目` 文字链接（轻收尾）。

### 6.4 前台路由表
| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/` | Home.vue | 搜索 + 推荐网格 |
| `/projects` | ProjectList.vue | 标签筛选 |
| `/project/:slug` | ProjectDetail.vue | 作品文章 |

## 7. 后台页面设计（管理端）

### 7.1 布局骨架
```
[ 侧边导航 220px ]  [ 内容区 ]
  ▸ 项目管理            工具栏：搜索 [状态▾] [+ 新增项目]
    标签管理            ── 路由出口（列表 / 编辑器 / 标签）──
```
- 登录后布局常驻；当前项用 `brand-soft` 底 + brand 文字标识。
- 路由守卫：未带 token 一律回 `/login`（见 7.6）。

### 7.2 登录 `/login`（FR-05、UC-05）
- 居中卡片（420px）：系统名 + 用户名 + 密码 + 主按钮"登录"。
- 背景用 `brand-deep` 深蓝整幅，卡片白色浮起——前台白墙的对照面，强化"后台 = 另一个空间"。
- 登录失败：卡片内联错误文案（"用户名或密码不正确"），不做 toast（避免刷屏）。
- 成功：存 token（localStorage + Pinia），跳 `/projects`。

### 7.3 项目列表 `/projects`（FR-06、UC-06/07/08）
- 内容头：标题"项目管理" + 右侧主按钮 **"+ 新增项目"**。
- 过滤工具行：搜索框（匹配标题）、状态下拉（全部/草稿/已发布/已下架）、技术标签下拉。
- 表格列：标题（含小封面缩略图）· 状态（彩色 tag）· 推荐（★/—）· 更新时间 · 操作（编辑 / 下架或发布 / 删除）。
- 删除弹确认（§5.6）；下架/发布原地 toggle + toast。
- 分页底部 Element `pagination`。

### 7.4 项目编辑器 `/projects/:id/edit`（FR-07、UC-06/07）—— 本系统最重要的后台页面
分两块，**左基础信息、右正文编排**会过长；采用上下两段式单页：

**上段：基础信息（字段 ↔ 04 表对齐）**
| 表单项 | 绑定字段 |
| --- | --- |
| 项目名称 | `projects.title` |
| 唯一标识 slug（自动从名称转拼音/保留人工改） | `projects.slug` |
| 一句话介绍 | `projects.summary` |
| 封面（上传 3:2，预览） | `projects.cover_id` |
| 技术栈摘要（可编辑字符串，下拉+回填 tag） | `projects.tech_stack` + `tags` 多选 |
| 成员 | `projects.members`（逗号分隔，前端胶囊输入） |
| 推荐开关 | `projects.recommended` |
| 状态 | `projects.status`（0 草稿 / 1 已发布 / 2 已下架） |

**下段：正文区块编排（作品文章）**
- 工具栏：`[+ 标题] [+ 文本] [+ 图片]`；已有序号、每行操作 `↑ ↓ 删除`。
- 图片按钮 → 上传（`POST /api/images`）→ 拿到 `image_id` 插入区块；上传区即时预览，可先插占位再后台处理。
- 顺序 = `project_sections.sort`，保存时按当前 DOM 顺序全量提交。
- 区块类型映射：`type=1 标题` / `2 文本` / `3 图片`（与 04 数据库一致）。
- **保存策略（关键）**：保存走 `PUT /api/projects/:id` 一次性提交"基础信息 + 完整正文区块数组"，后端事务内全量替换该项目的 sections（对应 CLAUDE.md 核心决策 1）。编辑器只维护本地一份可排序数组，**不做逐区块保存**。

**页尾固定操作条**：`保存草稿`（status=0）/ `发布`（status=1）· `预览`（新窗口 `/project/:slug` 前台）· 取消返回。

### 7.5 标签管理 `/tags`（FR-08、UC-09）
- 表格：名称 · 创建时间 · 关联项目数 · 操作（删除，有关联项目时给提示）· 顶部"新增标签"输入。
- 标签名唯一，重复命名前端即时报错。

### 7.6 后台路由与守卫
| 路由 | 页面 | 守卫 |
| --- | --- | --- |
| `/login` | Login.vue | 已登录则跳 `/projects` |
| `/projects` | ProjectList.vue | 需 token |
| `/projects/:id/edit` | ProjectEditor.vue | 需 token |

- Axios 拦截器：自动附 `Authorization: Bearer`；收到 401 清 token 跳登录；业务错误码 → 统一解析提示。

## 8. 响应式与无障碍（前台重点）

- 移动端：导航折叠为一行（标 + 汉堡/或简化为"全部"链接），卡片 1 列，详情封面通栏、正文 720px 自适应到 16px 基准；搜索框顶部全宽。
- 键盘：所有交互可 Tab 到达；联想下拉支持 ↑↓ + Enter + Esc。
- 焦点：`:focus-visible` 用 2px brand 描边；不靠 hover 传达关键信息。
- 动效：遵守 `prefers-reduced-motion`。
- 对比度：全部满足 §3.1；禁用态用 `muted` 文字而不是只剩浅灰（图标场景例外需搭配文字）。

## 9. 性能与实现提示（V1）

- 列表/详情接口做**页级缓存**（Pinia 简单缓存最近 N 页 + 回到首页用缓存，减少重复请求）。
- 封面统一 3:2 裁剪 + 后端可输出压缩尺寸（V1 若 BLOB 无法动态压缩，前端用 `loading="lazy"` + `decoding="async"` 兜底）。
- 搜索防抖 200ms、取消过期请求（AbortController），保证 500ms 内响应体验（非功能需求 01）。
- Element Plus 按需引入（`unplugin-vue-components`），避免后台包体过大。

## 11. 设计自查（为什么不是模板方案）

- 拆掉了通用"大图 hero + 统计数字 + 渐变"开场：首页直接给内容，符合本项目"打开即浏览"的需求而非展示型 landing。
- 无衬线 + 宋体的双字体策略来自**产品语义**（作品可阅读），而非美观偏好；后台刻意排除宋体以区分两种模式。
- 卡片无多余内阴影/双层圆角；唯一的"装饰性"徽标（★推荐）是业务字段 `recommended` 的可视化，非纯装饰。
- 暖橙占比压到 <3%，避免沦为"深蓝+橙"的通用后台配色套版——它的存在只为让"推荐作品"在 30 件里被第一眼看见。
