## 1. 前台页面地图与数据依赖（新版模型）

```
/public
 ├── HomeView        `/`             → GET /api/home（推荐卡片 + 分类 + 热门兜底）
 │    └─ SearchBox（中央搜索）        → GET /api/search/suggest（联想，防抖）
 │                                    → Enter 跳 /projects?q=<kw>（结果列表）
 ├── ProjectListView `/projects`     → GET /api/projects（分类/标签/关键词/排序/分页）
 │                                    ← 可来自：全部 或 搜索结果(q) 或 分类筛选
 └── ProjectDetailView `/project/:id`→ GET /api/projects/:id（详情，服务端计浏览量）
```

> 关键约定（贯穿全文件）：
> - 前台只消费 **published** 项目；后端在 service 层统一过滤，前端不传状态参数。
> - 列表接口统一 `page/page_size`（默认 20，≤100）+ 返回 `total/has_more`，前端"加载更多"= page+1。
> - 接口输出 **camelCase** 字段（后端 DTO 用 Go json tag 转好），前端 `types.js` 直接对齐，不做蛇形→驼峰转换。

## 2. 设计原则（前台）

沿用 `08` §2（白底留白、作品登台、宋体作品感、反馈动效＞观赏动效、封面即主角），并新增本方案专属约束：

1. **搜索是第一条路，不是附属品**：首屏从上到下 = 导航条 → 搜索 → 内容。搜索框是本页视觉与交互的"一级入口"。
2. **列表用"卡片 + 加载更多"，详情用"读文章"**：浏览节奏靠滚动延续，不给读者翻页打断。
3. **详情页内容即数据**：正文渲染完全由后端下发的 `blocks[]` 驱动，前端**不感知、不硬编码**正文结构；封面是数据 `cover_url`，不是写死的装饰图。
4. **状态齐全，不裸奔**：加载（骨架屏）/空（引导）/错误（可重试）/404（返回全部）四种状态缺一不可。

## 3. Reddit 式搜索框（重点设计）

> 参考 Reddit 顶栏搜索的体验目标：**输入即联想、一击即达内容、键盘可全流程操作**。映射到本站 = 联想项点入直达详情，回车进"搜索结果列表页"。

### 3.1 位置与视觉（首页首屏）

```
┌────────────────────────────────────────────────────────┐
│  优秀项目展示系统(文字标)          全部项目     分类▾     │
│                                                        │
│          ┌────────────────────────────────┐            │
│          │ 🔍  搜索项目名、技术栈、关键词…     [×]      │  ← 560px 居中，圆角14
│          └────────────────────────────────┘            │
│   ┌───────────────┐  ┌───────────────┐  ┌───────────┐  │  ← 联想下拉(max 6)
│   │ [封面缩略]     │  │ [封面缩略]     │  │ [封面缩略]  │  │
│   │ MyGoVoice     │  │ 智能问答平台    │  │ Go工具箱    │  │
│   │ A lightweight │  │ 基于大模型…     │  │ 代码…       │  │
│   │ Go… │★推荐    │  │ [Go] 高亮      │  │ [Go]        │  │
│   └───────────────┘  └───────────────┘  └───────────┘  │
│                  ── 更多结果：按 Enter ──                │
└────────────────────────────────────────────────────────┘
```

### 3.2 组件树与职责

```
SearchBox（组件：输入框本体，自包含下拉）
 ├─ <input>：占位"搜索项目名、技术栈、关键词…"；focus 描边 brand；非空显示 [×] 清除
 ├─ SearchSuggestions（v-if=open && keyword）：联想列表
 │    ├─ ProjectSuggestionItem（封面缩略 64px + 名称(高亮) + summary 截断 + ★推荐可带）
 │    └─ footer："没有匹配「kw」的项目？回车查看全部结果"
 └─ useSearch(keyword)（组合式逻辑，可单测）
      ├─ debounce 200ms
      ├─ AbortController 取消过期请求
      ├─ 命中词高亮切分工具 highlightParts(text, kw)
      └─ 键盘状态机：↑↓ 移动 activeIndex / Enter 跳转 / Esc 关闭
```

### 3.3 交互状态机

| 触发 | 行为 |
| --- | --- |
| 输入（>0 字） | 防抖 200ms → `GET /search/suggest?keyword=` → 开下拉；loading 显示细条骨架 |
| 输入清空 | 关闭下拉；页面停留在首页内容 |
| 下拉项 hover / ↑↓ | `activeIndex` 高亮（brand-soft 底） |
| 回车（有 active） | 进该项目详情 `/project/:id` |
| 回车（无 active 或点了 footer） | 跳 `/projects?q=<keyword>` 搜索结果列表 |
| 点击联想项 | 直达 `/project/:id` |
| 点击联想项内文字高亮 | 命中片段以 `brand-soft` 底标出 |
| Esc / 点击外部 | 关闭下拉、清 active，不清输入 |
| 无结果 | 下拉显示 footer 引导 + 空态图标；回车仍可看全部结果页 |
| 请求失败 | 下拉静默收起（首页内容不受影响），不弹错误 |

**防抖参数**：200ms；输入长度 trim 后 <1 不请求。**联想上限**：默认 6 条（`limit=6`）。**命中字段**（后端）：`name`（权重最高）→ `tags.name` → `summary` → `blocks.text_content`。

### 3.4 搜索结果页复用逻辑

搜索结果不单独建"复杂搜索页"，而是**复用全部项目列表页**：`/projects?q=xxx`。
- URL 携带关键词 → 页面标题区显示 `搜索「xxx」，共 N 个结果`，右侧 [清空] 回全部。
- 数据走 §4 的 `GET /projects?keyword=`，与标签/分类筛选**可叠加**（`?q=&category_id=&tag_id=&sort=`）。
- 搜索框在 `/projects` 页保留在页头（缩小版 380px），支持二次搜索。→ 符合需求"搜索 → 内容，而非搜索 → 复杂搜索页 → 再点项目"。

## 4. 后端 API 设计方案（前台，前端友好）

### 4.1 设计约定（让前端"好调用"）

| 约定 | 说明 |
| --- | --- |
| 统一响应 | `{ code, message, data }`，code=0 成功；`data` 直接可用，前端 axios 拦截器解包后**业务代码只见 data** |
| 错误可读 | 4xx/5xx：后端 message 给人类可读文案；前端按 `errcode` 映射兜底提示 |
| 字段 camelCase | DTO 输出 `coverUrl`、`isRecommended`、`viewCount`… 前端零转换 |
| 列表页能力 | 一律 `page/page_size` 且返回 `total`/`has_more`，支持"加载更多"不依赖后端感知 |
| 前台只见 published | 后端 service 过滤；前端 URL 里不出现 status |
| id 路由 | 详情 `:id` 为数字，避免 SEO 路由复杂度（V1 确认） |
| 只传必要的 | 列表/联想返回精简 CardDTO，详情返回 DetailDTO；**不整表回吐** |

### 4.2 前台接口清单（REST）

| 方法 | 路径 | 用途 | 页面 |
| --- | --- | --- | --- |
| GET | `/api/home` | 首页聚合：`recommended[]`(按 recommend_order，≤12) + `categories[]` + `latest[]`(3 兜底) | Home |
| GET | `/api/projects` | 项目列表：`?keyword&category_id&tag_id&sort=recommended\|newest\|views&page&page_size` | /projects、搜索结果 |
| GET | `/api/search/suggest` | 联想：`?keyword&limit=6`（返回精简卡片） | SearchBox |
| GET | `/api/projects/:id` | 详情：基础信息 + category + tags[] + blocks[] + members[]（服务端 view_count+1 后返回现值） | /project/:id |
| GET | `/api/categories` | 分类列表（sort_order 升序） | Home / /projects 筛选 |
| GET | `/api/tags` | 技术栈标签列表（含关联计数可选） | /projects 筛选 |
| POST | `/api/projects/:id/views` | （二期/可选）显式浏览量上报，替代 GET 自动 +1 | Detail onMounted |

### 4.3 关键接口请求/响应（前端视角的 JSON 契约）

**首页 `GET /api/home`**
```json
{ "code": 0, "message": "ok",
  "data": {
    "recommended": [
      { "id": 3, "name": "MyGoVoice", "summary": "A lightweight Go code structure announcer for VS Code.",
        "coverUrl": "/uploads/p3-cover.webp", "tags": ["Go","AST","VS Code"],
        "isRecommended": true, "categoryId": 1 }
    ],
    "categories": [ { "id": 1, "name": "开发类" }, { "id": 2, "name": "AI" } ]
  } }
```

**列表 `GET /api/projects?keyword=Go&sort=views&page=1&page_size=20`**
```json
{ "code": 0, "message": "ok",
  "data": { "list": [ /* CardDTO，同推荐卡片结构 */ ],
            "total": 14, "page": 1, "page_size": 20, "has_more": true } }
```

**联想 `GET /api/search/suggest?keyword=go&limit=6`**
```json
{ "code": 0, "message": "ok",
  "data": [ { "id": 3, "name": "MyGoVoice", "summary": "A lightweight Go code…",
              "coverUrl": "/uploads/p3-cover.webp", "tags": ["Go"] } ] }
```

**详情 `GET /api/projects/3`**
```json
{ "code": 0, "message": "ok",
  "data": {
    "id": 3, "name": "MyGoVoice",
    "summary": "A lightweight Go code structure announcer for VS Code.",
    "coverUrl": "/uploads/p3-cover.webp",
    "category": { "id": 1, "name": "开发类" },
    "tags": ["Go", "AST", "VS Code"],
    "members": [ { "name": "张三", "role": "后端开发" },
                 { "name": "李四", "role": "前端开发" } ],
    "viewCount": 1201,
    "publishedAt": "2026-08-30",
    "blocks": [
      { "type": "heading",    "text": "项目介绍" },
      { "type": "paragraph",  "text": "MyGoVoice 是…" },
      { "type": "image",      "url": "/uploads/p3-shot1.webp", "caption": "核心界面" },
      { "type": "heading",    "text": "项目成果" },
      { "type": "paragraph",  "text": "获得…" }
    ]
  } }
```

### 4.4 详情浏览量策略（一期/二期）

- **一期**：`GET /projects/:id` 命中 published 详情时服务端 `view_count+1` 并返回现值。简单；代价是"刷新重复计数"，30 项目规模可接受。
- **二期（Redis）**：改为 `POST /projects/:id/views`，Redis 计数 + 按 IP/会话去重 + 定时落库；`GET` 返回缓存值。
- 前端在两者下都**零改动**：详情页只需展示响应里的 `viewCount`（本方案契约已含）。

### 4.5 前端调用友好度清单（交付后端对照）

- [ ] 所有返回走 `{code,message,data}`，业务失败用 HTTP 2xx + code≠0 也能解析（拦截器统一）
- [ ] 数组必为数组、缺省给默认（空数组/0/空串），**不出现 null 需要前端判空的分支爆炸**
- [ ] 分页永远有 `total`、`has_more`
- [ ] 列表/联想/详情字段名是 camelCase 且三处一致（同一份 CardDTO 复用）
- [ ] 图片返回相对路径（`/uploads/…`），前端用 `VITE_API_BASE_URL` 拼全——开发/生产/OSS 前缀切换只改配置

## 5. 前端 UI 设计（页面级）

> 视觉令牌沿用 `08` §3：画布 `#F7F8FB` / 表面白 / hairline `#E6E9F0` / ink `#1E2433` / brand `#0D4A8E` / accent 橙 `#E0700A`(★推荐，占比<3%)；宋体做作品名与正文、无衬线做 UI；间距 4 基数；封面统一 **3:2**；内容宽 **1180px**；网格 3/2/1 列。

### 5.1 首页 HomeView（= 搜索 + 内容，无巨型 hero）

```
[nav] 优秀项目展示系统       全部项目    [分类 ▾]
[中央搜索框 SearchBox（§3）]
──────── 推荐项目 ────────
[★ 推荐卡片网格] × N（recommended，N≤12，3/2/1 响应式）
──────── 最新上架 ────────
[卡片网格] × 3（latest 兜底，补足首屏）     [查看全部项目 →]
```
- 导航：bg 同画布、无盒装；"分类 ▾"为**下拉跳转** `/projects?category_id=`（不做站内二级路由）。
- 骨架：推荐区 3 张 3:2 灰块。

### 5.2 全部项目 ProjectListView（含搜索结果、可作 `/projects` 首页以外的唯一列表页）

```
[nav] ……
h1：全部项目   （若 ?q=）→ 搜索「Go」，共 14 个结果  [清空]
筛选条：[分类 chips: 全部/开发类/AI/…]  [排序 ▾ 推荐/最新/浏览最多]
[项目卡片网格]
[加载更多 ▾]（按钮；has_more=false 时消失，尾部显示"已经到底啦"）
```
- 数据流：`route.query`（q/category_id/sort）→ watch → 请求 → 网格；切分类/排序即重置到第 1 页。
- 空态：`没有匹配的项目` + 建议动作（清空筛选）。

### 5.3 项目卡片 ProjectCard（核心复用组件，一眼懂）

```
┌───────────────────────┐
│  [ 封面 3:2 ]        ★ │   ← ★=isRecommended，暖橙 12px 徽标，hover 封面放大 1.02 + 阴影提升(120ms)
```

### 6.2 分层与依赖方向（禁止向上引用）

```
views（页面装配：路由参数 → store → 组件）
  │
stores（列表筛选/缓存等跨组件状态；不含请求细节）
  │
components（无业务请求；只通过 props 收数据、emit/router 发事件）
  │
api（唯一持 axios：http.js 拦截 → projects/home/tags 函数 → 返回 Promise<data>）
  │
router + styles + composables（纯工具）
```

### 6.3 路由（Vue Router 4）

| 路由 | 组件 | 说明 |
| --- | --- | --- |
| `/` | HomeView | 搜索 + 推荐 + 最新 |
| `/projects` | ProjectListView | query：`q` / `category_id` / `tag_id` / `sort` |
| `/project/:id` | ProjectDetailView | id 数字；详情缓存命中则不重复请求 |

- 路由统一 `meta.title` → `document.title`（"MyGoVoice | 优秀项目展示"）。
- 从列表进详情后点"返回"→ 列表保留原滚动位置（`keep-alive` + 滚动记忆，V1 简单方案：详情页返回用 `router.back()`，列表页数据放 store 缓存不重新拉）。

### 6.4 状态与请求策略（Pinia + Axios）

- **列表状态进 store**：q/category/sort 与请求结果放 Pinia `projects` store——离开列表页再返回不丢、不重拉；切筛选时**只重置第 1 页**（`page=1`），加载更多才 `page+1` 追加。
- **详情页级缓存**：`cache.js` 存最近浏览 N 个 detail，返回不重复请求（配合浏览记忆）。
- **并发/过期控制**：搜索联想每次请求带 `AbortController`；列表快速切分类时丢弃旧响应（对比请求 seq）。
- **错误策略**：网络/5xx → ErrorState 整块 + 重试；业务 code≠0 → toast 文案；404 → 详情专用 404 页。
