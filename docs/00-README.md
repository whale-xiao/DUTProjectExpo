## 一、项目一句话定位

> **一个可以浏览、发现、阅读"实训优秀项目作品"的内容网站。**

不是 30 条项目记录的 CRUD，而是 **30 件作品的展示、发现与阅读体验**。借鉴 Reddit（内容发现）、Pixiv（作品展示）、小红书（卡片浏览），**不引入社交机制**（无点赞、评论、收藏、关注、热榜）。

## 四、核心设计决策（贯穿实现）

1. **项目详情 = 可编排的"作品文章"**：正文由有序内容块（heading/paragraph/image）构成；后台一次事务全量保存。
2. **搜索是一级交互**：首页中央搜索框 → 即时联想（`/api/search/suggest`）→ 直达详情；回车进列表（`/api/projects?keyword=`）。
3. **前台沉浸内容、后台高效编辑**：两套完全不同的体验。
4. **图片 URL 化**：存 `/uploads/`（V1 本地 → 二期 OSS），不用 BLOB。
5. **详情路由数字 id**：`/project/:id`（编码期确认）。
6. **明确不做**：点赞、评论、收藏、关注、社交关系、热榜；多租户/RBAC 等企业功能（后台为若依形态单管理员精简版）。
